# A1.06 · Luồng phương án → xác nhận → executor

**Người:** A · **Ước tính:** 3h · **Ngày:** 29/9 · **Skill:** `langgraph-human-in-the-loop` · **ĐƯỜNG GĂNG**

## Mục tiêu
Khi khách cần đặt / đổi lịch: agent gọi `find_options`, tạo `Proposal`, API ký token; chỉ khi khách bấm Xác nhận mới gọi `src.executor.run`.

## Vì sao
Ràng buộc gốc của đề: hành động ảnh hưởng khách phải được xác nhận trước. Bước 3 của demo MVP.

## File
- tạo `src/agents/nodes/confirm.py` — node `confirm_and_execute` dùng `interrupt()`
- sửa `graph.py` — cạnh coordinator → confirm
- state: `proposal: Proposal | None`

## Đầu vào → đầu ra (dữ liệu demo `contracts/fixtures/demo_world.yaml`)
- Sau tin chủ động, khách chọn OPT-1 → Proposal(action="reschedule", params={appointment_id: A-20931, option_id: OPT-1}) → token → /api/v1/confirm

## Các bước
1. Agent KHÔNG import `src.tools`; chỉ tạo `Proposal`
2. Token do API ký (`src.executor.token.issue_token`), LLM không thấy
3. `interrupt()` dừng graph; `/api/v1/confirm` resume hoặc gọi thẳng `executor.run`
4. Khách đổi ý → quay về coordinator
5. Node chứa `interrupt()` CHẠY LẠI từ đầu khi resume → token + nonce sinh ở node TRƯỚC (lưu state) hoặc tất định từ (thread_id, hash proposal)
6. Executor gọi ở node riêng SAU resume; resume chỉ bằng `Command(resume=token)`
